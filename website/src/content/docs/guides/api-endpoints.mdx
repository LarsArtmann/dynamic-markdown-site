## Content Routes

| Endpoint | Method | Description                        |
| -------- | ------ | ---------------------------------- |
| `/`      | GET    | Root directory listing             |
| `/*path` | GET    | Markdown file or directory listing |

Directory pages show a card grid with file/folder icons, titles, and last modified dates. Directories are sorted first, then files, alphabetically.

### Path Resolution

- `.md` extension is optional: `/about` and `/about.md` both work
- Trailing slashes are normalized
- Case-insensitive matching as a fallback
- Non-markdown files (images, PDFs, JSON) are served as raw assets

## Health Probes

The server exposes the standard Kubernetes three-probe set (backed by [go-health](https://github.com/larsartmann/go-health)) plus a `/health` readiness alias:

| Endpoint     | Method | Question it answers                                            | Failure behavior                          |
| ------------ | ------ | -------------------------------------------------------------- | ----------------------------------------- |
| `/healthz`   | GET    | Is the process alive? (never checks dependencies)              | Always 200 while serving                  |
| `/readyz`    | GET    | Are critical dependencies reachable?                           | 503 only when the content repository fails |
| `/startupz`  | GET    | Has boot completed?                                            | 503 until the first successful sweep      |
| `/health`    | GET    | Alias of `/readyz` (Docker `HEALTHCHECK` / `healthcheck` subcommand) | Same as `/readyz`                    |

Readyz and the `/health` alias return JSON with a pass/warn/fail roll-up, version, uptime, and per-dependency checks. The content repository is the only **critical** dependency — its failure returns `503` with `"status": "fail"`. A missing D2 binary degrades diagram rendering but is **non-critical**: the response stays `200` with `"status": "warn"` and the renderer check carries the reason.

```json
{
	"status": "pass",
	"version": "1.0.0",
	"uptime": "2h30m",
	"checks": {
		"repository": { "status": "pass" },
		"renderer": { "status": "fail", "error": "d2 diagram renderer unavailable; diagrams render as code blocks" }
	}
}
```

Readiness verdicts are cached and refreshed every 15 seconds, so orchestrator probes never fan out into the storage backend.

## Refresh

```http
GET /refresh
POST /refresh
```

Reloads all content from the storage backend and invalidates the cache. Rate limited to 10 requests per minute per IP.

```json
{
	"status": "success",
	"message": "content repository refreshed",
	"lastModified": "2026-07-13T...",
	"totalFiles": 42,
	"totalDirs": 8,
	"duration": "15ms"
}
```

## Search

```http
GET /search?q=your+query
```

Full-text search with relevance scoring:

- **Exact title match:** 100%
- **Partial title match:** 50%
- **Content body match:** 30%

Results include highlighted snippets with `<mark>` tags.

## Sitemap

```http
GET /sitemap.xml
```

XML sitemap for search engines. Includes all non-draft pages with priority and changefreq metadata.

## Robots

```http
GET /robots.txt
```

Robots file for crawlers. Allows all user agents and points to the sitemap.

## Metrics

```http
GET /metrics
```

Prometheus-format metrics for monitoring.

## Cache Stats

```http
GET /cache/stats
```

Returns cache hit/miss statistics:

```json
{
	"hits": 100,
	"misses": 5,
	"hitRate": 0.95
}
```

## Static Assets

```http
GET /static/*path
```

CSS, favicon, and other embedded assets. Served with immutable cache headers.

## Live Reload (Dev Mode Only)

```http
GET /api/live-reload
```

Server-Sent Events endpoint for live reload. The browser connects and receives reload events when files change. Only available in dev mode (`-dev` flag).
